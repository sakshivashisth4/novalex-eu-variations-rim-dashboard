  
\# EMA Variation Logic

\#\# Purpose

This document explains the EU variation logic used in the Novalexib project.

The project simulates post-authorisation variation management for a fictional EU-approved product.

\#\# Variation Categories

The project uses the following variation categories:

| Category | General Meaning |  
|---|---|  
| Type IA | Minor variation, generally do-and-tell |  
| Type IAIN | Minor variation requiring immediate notification |  
| Type IB | Minor variation requiring assessment |  
| Type II | Major variation requiring prior approval |  
| Extension | Major change treated as an extension application |

\#\# Type IA

\#\#\# Description

Type IA variations are minor changes that generally have minimal impact on quality, safety, or efficacy.

\#\#\# Examples

\- Minor administrative updates  
\- Editorial changes  
\- Minor manufacturing documentation updates  
\- Minor updates with no significant impact

\#\#\# Risk Level

Usually Low.

\#\#\# Expected Documents

\- Cover letter  
\- Application form / eAF  
\- Updated affected documents, if applicable

\#\#\# Dashboard Interpretation

Type IA submissions are expected to have lower query burden and shorter timelines.

\#\# Type IAIN

\#\#\# Description

Type IAIN variations are minor changes requiring immediate notification.

\#\#\# Examples

\- Certain administrative updates  
\- Urgent but minor regulatory information changes  
\- Changes that must be notified immediately after implementation

\#\#\# Risk Level

Low to Medium.

\#\#\# Expected Documents

\- Cover letter  
\- Application form / eAF  
\- Supporting documentation  
\- Updated product information, if applicable

\#\#\# Dashboard Interpretation

IAIN submissions are expected to be quick but still require accurate notification and documentation.

\#\# Type IB

\#\#\# Description

Type IB variations are minor variations that require authority assessment before acceptance.

\#\#\# Examples

\- Moderate quality changes  
\- Certain specification updates  
\- Moderate process changes  
\- Stability or packaging updates with moderate impact

\#\#\# Risk Level

Medium.

\#\#\# Expected Documents

\- Cover letter  
\- Application form / eAF  
\- Updated CTD sections  
\- Supporting justification  
\- Quality documentation where applicable

\#\#\# Dashboard Interpretation

Type IB submissions may generate queries but are usually less complex than Type II.

\#\# Type II

\#\#\# Description

Type II variations are major variations that may significantly impact quality, safety, or efficacy.

\#\#\# Examples

\- Major manufacturing site changes  
\- Major process changes  
\- Significant specification changes  
\- Stability strategy changes  
\- New indication or significant clinical/safety update  
\- Major labelling or risk management changes

\#\#\# Risk Level

Medium to High, often High.

\#\#\# Expected Documents

\- Cover letter  
\- Application form / eAF  
\- Module 1 updates  
\- Module 2 summaries  
\- Module 3 quality documentation  
\- Module 5 clinical documentation, if applicable  
\- GMP documentation  
\- Stability data  
\- Updated product information, if applicable

\#\#\# Dashboard Interpretation

Type II submissions are expected to drive:

\- Higher document workload  
\- Longer review timelines  
\- More agency queries  
\- Higher implementation risk  
\- More archive and publishing oversight

\#\# Extension

\#\#\# Description

Extension applications are used for major product changes that go beyond standard variations.

\#\#\# Examples

\- New strength  
\- New pharmaceutical form  
\- New route of administration  
\- Major product presentation change

\#\#\# Risk Level

High.

\#\#\# Expected Documents

\- Full supporting CTD package  
\- Product information updates  
\- Quality documentation  
\- Clinical or bioequivalence data, if applicable  
\- Annex/product presentation information

\#\#\# Dashboard Interpretation

Extension-type submissions are treated as high complexity and may have longer timelines.

\#\# Risk Logic Used in the Project

| Variation Category | Typical Risk |  
|---|---|  
| Type IA | Low |  
| Type IAIN | Low to Medium |  
| Type IB | Medium |  
| Type II | Medium to High |  
| Extension | High |

\#\# Query Logic Used in the Project

Agency queries are concentrated around:

\- Module 3 quality sections  
\- Drug substance impurities  
\- Drug product specifications  
\- Stability data  
\- GMP documentation  
\- Process validation  
\- Labelling updates  
\- Administrative clarifications

\#\# CTD Module Logic

| Module | Use in Project |  
|---|---|  
| Module 1 | Administrative and regional documents |  
| Module 2 | Quality/clinical summaries |  
| Module 3 | Quality and CMC data |  
| Module 5 | Clinical data, where applicable |

\#\# Dashboard Logic

The EMA Variation Reference Intelligence page visualises:

\- Variation category vs risk level  
\- Preapproval requirement by type  
\- Variation type by example category  
\- Common required documents  
\- Regulatory burden by variation category

\#\# Disclaimer

The variation logic in this project is simplified for educational and portfolio purposes. Actual classification should always be based on current EU variation regulations, product-specific context, and health authority guidance.
