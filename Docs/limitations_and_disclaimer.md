\# Limitations and Disclaimer

\#\# Disclaimer

This is a fictional regulatory affairs portfolio project created for learning and demonstration purposes.

Novalexib is a fictional product. The data does not represent real EMA submissions, real Veeva Vault configuration, real company regulatory records, real patient data, or confidential pharmaceutical information.

\#\# Not Official Regulatory Advice

This project is not intended to provide regulatory advice.

The variation classifications, timelines, query examples, risk levels, CTD mappings, and workflow assumptions are simulated. Actual regulatory decisions should be based on current regulations, official guidance, product-specific context, and expert review.

\#\# Fictional Data

All data used in this project is simulated, including:

\- Product information  
\- Submission records  
\- Agency queries  
\- CTD document plans  
\- Document lifecycle records  
\- Publishing records  
\- Archive records  
\- Lifecycle milestones  
\- Risk levels  
\- Implementation timelines

\#\# Simplified Veeva Vault RIM Model

The project is inspired by Veeva Vault RIM-style workflows but does not represent actual Veeva Vault configuration.

Actual RIM systems include more advanced features such as:

\- Configurable object models  
\- Controlled document workflows  
\- User permissions  
\- Audit trails  
\- Electronic signatures  
\- Automated publishing rules  
\- Submission validation integrations  
\- Health authority correspondence management  
\- Country-specific lifecycle tracking

This project simplifies those concepts into Excel, Python, and Power BI for portfolio demonstration.

\#\# Simplified EMA Variation Logic

The EMA variation logic is simplified for learning purposes.

Actual EU variation classification depends on:

\- Product type  
\- Procedure type  
\- Specific change details  
\- Annexes and classification guidelines  
\- Health authority interpretation  
\- Quality, safety, and efficacy impact  
\- Product-specific regulatory history

\#\# Dashboard Limitations

The Power BI dashboard is designed for demonstration and storytelling. It is not intended for operational regulatory use.

Known limitations include:

\- Simulated records only  
\- Simplified relationships  
\- Limited validation logic  
\- No real electronic submission integration  
\- No actual health authority gateway connection  
\- No true audit trail  
\- No real document repository  
\- No controlled user access model

\#\# Data Quality Limitations

Because the project data is simulated, some values are generated based on assumptions, such as:

\- Query response dates  
\- Review durations  
\- Publishing readiness percentage  
\- Archive QC status  
\- Risk levels  
\- Owner assignments  
\- Document status transitions

These values are intended to create a realistic portfolio scenario, not to represent actual regulatory performance.

\#\# Intended Audience

This project is intended for:

\- Regulatory affairs portfolio demonstration  
\- Power BI dashboard demonstration  
\- Data analytics skill demonstration  
\- Regulatory operations workflow learning  
\- GitHub and LinkedIn portfolio use

\#\# Not Intended For

This project should not be used for:

\- Actual regulatory submissions  
\- Health authority communication  
\- Product compliance decisions  
\- Clinical or patient decision-making  
\- Company regulatory records  
\- Veeva Vault implementation guidance

\#\# Summary

This project demonstrates how regulatory affairs workflows can be structured, automated, and visualised using a fictional EU post-authorisation product scenario. It is intended to show understanding of regulatory lifecycle management, submission tracking, agency query handling, CTD content planning, publishing readiness, and archive oversight.
